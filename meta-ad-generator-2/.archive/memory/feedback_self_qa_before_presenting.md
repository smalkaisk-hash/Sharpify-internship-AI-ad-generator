Before presenting any ad set (LV or ENG, client or Sharpify), I must do a full self-QA pass. No exceptions, no "spot-check a few and ship it."

**Mandatory checks before user review:**

1. **View every rendered PNG** — not a sample of 2-3. If there are 12 ads, I read 12 PNGs. Catches headline wrapping issues, layout overflow, photo/text overlap, typos specific to one niche, orphan words.

2. **Native-speaker plausibility check on every headline** — read each headline out loud. Does a real tradesperson in that market actually say this? Watch for LV→ENG direct translations that read awkward ("You roof homes," "You finish the windows"). Plural object nouns are a classic trap (windows, tiles, shingles) because they have multiple unrelated meanings.

3. **Offer/bonus verification** — any value-prop text on the creative (chips, gifts, badges, price slashes) must match the actual landing page / product structure. If I'm writing "Free X included" I need to confirm X really is included. Fetch the landing page if unsure.

4. **After any font/layout/template change: regenerate ALL variants, view ALL PNGs** — one fix can break other niches differently. Do not present until every variant has been re-rendered AND re-viewed.

**Why:** User (2026-04-15) pushed back after a session where I made the user correct: "you roof homes" phrasing, "Playbook included" wrong offer, a 3-line headline I should have caught myself, and "you finish the windows" ambiguity. Each correction cost a round-trip. User's feedback: "why do I need to go over every single ad, for some simple text or layout... is there a way we can avoid this in the future?"

**How to apply:** Bake this into every ad-generation workflow (reklamas-meta-sharpify, reklamas-meta-sharpify-eng, full-pipeline client ads). Do the self-QA silently — only surface issues or the final set. The user's job is strategic review, not proofreading.

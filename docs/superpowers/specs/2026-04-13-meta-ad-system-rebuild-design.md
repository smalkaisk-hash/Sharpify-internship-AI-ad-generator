# Meta Ad Generator — System Rebuild Design

**Date:** 2026-04-13
**Status:** Ready for implementation
**Owner:** Niks Jansons (Sharpify)

---

## 1. Context

The existing `claude-ad/` system produces inconsistent Meta ads because **Claude writes the HTML for each ad from scratch**. This is the opposite of how production AI ad platforms work (Meta Advantage+, Google PMax, Canva Magic, AdCreative.ai, Smartly.io, Pencil). Those systems all separate:

- **Template** (layout + typed slots + constraints) — authored once, reused many times
- **Brand Kit** (color/font/logo tokens) — per client
- **Copy Pack** (actual slot values for one ad) — generated by AI per variant

and render deterministically: `render(template, brand_kit, copy_pack) → HTML → PNG`.

AI is confined to (a) generating copy-packs as JSON against a schema, (b) picking templates, (c) reviewing output. **Layout is code, not LLM.** This is what delivers consistency at scale.

This spec rebuilds the system as **two fully independent folders** (`client-ads/` and `sharpify-ads/`) each with their own copy of the engine, their own templates, and their own brand kits. No shared code — each folder evolves at its own pace. Creative steps use isolated **sub-agents** to prevent drift; mechanical steps are plain scripts.

The existing `claude-ad/` folder stays as reference, to be deleted once the new system is proven.

---

## 2. Goals & non-goals

**Goals**
- Consistent output across all generated ads (same template fed the same inputs → visually identical result)
- Clean separation between client work and Sharpify's own ads
- Each piece (scraper, renderer, validator, copywriter) is a single file with one responsibility — trivially swappable
- Creative steps (copy, strategy, review) run in isolated sub-agent contexts
- Workflow survives being handed to a fresh Claude session — no tribal knowledge required

**Non-goals**
- Shared engine between the two folders (explicit design choice — keep them independent)
- Migrating existing `claude-ad/` templates 1:1 (starting fresh)
- Production deployment / hosted service (local-only)
- Video ad generation (stays in `remotion-videos/`, out of scope here)

**Why fully separate folders?** The user wants mental isolation. Working on client ads should never touch Sharpify code, and vice versa. Yes, we duplicate `engine/`. ## 4. The three-layer architecture

Every ad is the intersection of three JSON artifacts:

### 4.1 Template (`templates/<id>/template.json`)

Defines the layout's slots and constraints. Authored by humans (or by Claude once, then frozen).

```json
{
  "id": "pas-headline",
  "name": "Problem-Agitate-Solution Headline",
  "aspect_ratio": "1:1",
  "dimensions": { "width": 1080, "height": 1080 },
  "slots": {
    "headline": { "type": "text", "max_chars": 40, "required": true },
    "subhead":  { "type": "text", "max_chars": 80, "required": true },
    "cta":      { "type": "enum", "values": ["Learn More", "Shop Now", "Get Started", "Book Now"], "required": true },
    "hero_image": { "type": "image", "ratio": "1:1", "required": false }
  },
  "layout_file": "layout.html",
  "allowed_frameworks": ["PAS", "AIDA"]
}
```

Plus `layout.html` — plain HTML/CSS using `{{slot_name}}` placeholders and CSS variables from the brand kit (`var(--color-primary)`, etc.).

### 4.2 Brand Kit (`clients/<client>/brand-kit.json`)

Per-client visual identity. Authored once per client; rarely changes.

```json
{
  "client_id": "naqaa-beauty",
  "name": "Naqaa Beauty",
  "colors": {
    "primary": "#C8A8D8",
    "accent":  "#F4E4E4",
    "bg":      "#FFFFFF",
    "text":    "#1A1A1A"
  },
  "fonts": {
    "display": "Playfair Display",
    "body":    "Inter"
  },
  "logo": {
    "primary": "assets/logo.svg",
    "mono":    "assets/logo-mono.svg"
  },
  "voice": {
    "tone": ["elegant", "warm", "aspirational"],
    "avoid": ["discount language", "urgency-heavy claims"]
  }
}
```

### 4.3 Copy Pack (`clients/<client>/copy-packs/<ad-id>.json`)

Slot values for ONE ad. Generated by the `copywriter` sub-agent. Must match its template's schema.

```json
{
  "ad_id": "naqaa-001",
  "template_id": "pas-headline",
  "framework": "PAS",
  "slots": {
    "headline": "Sensitive skin flaring up again?",
    "subhead":  "Clean, dermatologist-tested formulas designed for reactive skin.",
    "cta":      "Shop Now"
  }
}
```

### 4.4 Render

```
render(template, brand_kit, copy_pack) → HTML → PNG
```

A Node script. Loads all three JSONs, validates the copy pack against the template schema, substitutes slot values into `layout.html`, injects brand-kit tokens as CSS variables, writes HTML, then runs Playwright to export PNG. No LLM involved in this step.

## 5. Sub-agents (creative steps only)

Defined as markdown files in `client-ads/.claude/agents/<name>.md` (same pattern for `sharpify-ads/`). Each has its own system prompt, narrow tool access, and isolated context when invoked via the Task tool.

### 5.1 `strategist` — picks templates + angles

**Input:** `brief.md` + `brand-kit.json`
**Output:** JSON with 6 ad plans: `[{ad_id, template_id, framework, angle, hook_idea}, ...]`
**Tools:** Read, Glob (can browse `templates/`, `reference/`)
**System prompt:** "You pick templates and angles. You do NOT write copy. You do NOT design layouts. Read the brief, read the brand voice, browse available templates, return a JSON plan for 6 ads that hit different angles."

### 5.2 `copywriter` — generates one copy pack at a time

**Input:** `template.json` + `brand-kit.json` + `{ad_id, framework, angle, hook_idea}` from strategist
**Output:** `copy-pack.json` matching the template's slot schema
**Tools:** Read
**System prompt:** "You write copy for ONE ad. You fill the template's slots, respecting char limits and the brand's voice. You MUST return valid JSON matching the schema. Use the specified framework (PAS/AIDA/etc.). No HTML, no design decisions."

### 5.3 `reviewer` — QA pass

**Input:** rendered PNG + the copy-pack that produced it
**Output:** `{pass: boolean, issues: [...], suggestions: [...]}`
**Tools:** Read (image-capable)
**System prompt:** "You review one ad for AI-slop, clarity, brand voice, and Meta ad best practices. Flag specific issues. Don't rewrite — only diagnose."

**What's NOT a sub-agent:** scraping, rendering, validating, PNG export, uploading. Those are scripts.

## 6. The orchestrator (main Claude)

The main Claude session you talk to. Runs the pipeline by chaining scripts and sub-agents. Does not do creative work directly.

### Typical workflow (client ads)

```
User: /new-client naqaa-beauty https://naqaa.com
  → orchestrator runs: node scripts/scrape-brand.js https://naqaa.com
  → orchestrator runs: node scripts/new-client.js naqaa-beauty
  → asks user to confirm/edit brand-kit.json

User: /make-ads naqaa-beauty
  → orchestrator reads clients/naqaa-beauty/brief.md + brand-kit.json
  → dispatches `strategist` sub-agent → returns 6 ad plans
  → shows plans to user for approval
  → for each plan: dispatches `copywriter` sub-agent → copy-pack.json
  → orchestrator runs: node engine/render.js for each → HTML + PNG
  → dispatches `reviewer` sub-agent on each PNG
  → surfaces any failed reviews to user
  → user approves → /upload naqaa-beauty (separate command, requires explicit approval)
```

Per memory rule `feedback_launch_approval.md`: **never auto-upload to Meta.** Upload is always a separate, explicit command.

## 7. Deterministic validator (`engine/validate.js`)

Runs after render, before PNG export. Pure code, no LLM. Checks:

- All required slots present
- No slot exceeds max_chars
- CTA value is in the allowed enum
- Text contrast ratio vs background ≥ 4.5:1 (WCAG AA)
- No text overflows its container (rendered height check via headless browser)
- Logo clearspace respected (if template specifies)

Fails loudly with specific messages. This kills 80% of inconsistency before the reviewer agent even looks.

## 8. Initial template set

Start with **4 templates per folder**, not 8+. Proven patterns only:

**client-ads/templates/:**
1. `pas-headline` — Problem-Agitate-Solution, image-optional
2. `split-comparison` — before/after or us/them, 2-column
3. `benefit-stack` — 3-4 benefit bullets, logo prominent
4. `single-testimonial` — quote + attribution + product

**sharpify-ads/templates/:**
1. `painpoint-list` — B2B, checkmark list of pains (per `feedback_emojis_in_ads.md`)
2. `feature-stack` — B2B, 🔹 feature list
3. `hook-question` — provocative question + subhead + CTA
4. `big-claim-proof` — bold claim on top, proof/social on bottom

More can be added later. Four is enough to validate the architecture.

## 9. Migration from `claude-ad/`

**Do NOT migrate existing templates.** Study them for aesthetic reference, but re-author fresh into the new schema. The existing ones were written per-ad (exactly the problem we're solving), so copy-pasting HTML defeats the purpose.

**Do reuse:**
- `claude-ad/reference/*.md` — copy frameworks, color theory, Meta specs. Copy into both new folders' `reference/`.
- `claude-ad/scripts/scrape-brand.js` — adapt as starting point for the new scraper.
- `claude-ad/scripts/export-png.js` — adapt as starting point for the new exporter.

**Delete (once new system produces one client's ads successfully):** the entire `claude-ad/` folder.

## 11. Build sequence

1. **Scaffold `client-ads/` only first.** Don't duplicate to `sharpify-ads/` until we've validated the design on one real client.
2. Write the three JSON schemas (templates, brand kits, copy packs).
3. Build `engine/render.js` + `engine/validate.js`. Test with a hand-written template + hand-written copy-pack + hand-written brand-kit. Verify you get a good PNG.
4. Author `pas-headline` template (first real template).
5. Write the three sub-agent markdown files.
6. Write slash commands.
7. Run end-to-end on **one existing client** (suggestion: `naqaa-beauty` — we have its data). Generate 6 ads. Review output.
8. Iterate on agents/prompts/validator based on what breaks.
9. **Only then:** duplicate the working engine + scripts + agents to `sharpify-ads/`, customize CLAUDE.md and templates for Sharpify's aesthetic.
10. Stop using `claude-ad/`. After 2 weeks of confidence, delete it.

## 12. Verification

End-to-end test on `naqaa-beauty`:

1. `/new-client naqaa-beauty https://naqaa.com` → brand-kit.json populated, brief.md scaffolded.
2. User fills in brief.md.
3. `/make-ads naqaa-beauty` → 6 rendered PNGs in `clients/naqaa-beauty/output/png/`.
4. All 6 PNGs pass `validate.js` (no overflow, contrast OK, all slots filled).
5. Reviewer sub-agent reports ≥ 4/6 passing QA on first run.
6. **Consistency check:** run the same copy-pack through render twice → pixel-identical PNGs. (Confirms determinism.)
7. **Isolation check:** make a trivial edit in `sharpify-ads/engine/render.js` → confirm `client-ads/` still works unchanged. (Confirms folder independence.)

## 13. Open questions for implementation session

These are small enough to decide during implementation — not blockers for starting:

- CSS framework: plain CSS vs Tailwind CDN? (Recommend: plain CSS — fewer moving parts, better template portability.)
- Template engine: Handlebars vs string-replace? (Recommend: Handlebars — handles conditionals for optional slots cleanly.)
- Image assets: inline as base64 vs file paths? (Recommend: file paths during dev, base64 only at export if upload needs it.)
- How the reviewer agent sees the PNG: Claude's vision capability via Read tool on the PNG file.
